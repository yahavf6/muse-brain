# Muse Brain: interface contracts (v1, local)

Everything below is fixed so the server, the hooks and the UI can be built in parallel. `docs/design.md` is the full design; this file is the wire format.

## Runtime

- Node 24 on PATH, TypeScript run directly (`node src/server.ts`, type stripping, no build). ESM (`"type": "module"`), imports carry `.ts` extensions.
- DB `~/.brain/brain.db` (override `BRAIN_DB`), WAL, `node:sqlite`. Port `4747` on `127.0.0.1` (override `BRAIN_PORT`). Env file `~/.brain/.env` loaded with `process.loadEnvFile` when present.
- Env: `TYPESAFE_API_KEY` (absent = Jev off), `BRAIN_JEV=on|off` (default on when key present), `BRAIN_JEV_GUARDS=shadow|on|off` (default `shadow`), `BRAIN_GUARDS=on|off` (default on; hooks honor it, falling back to grepping `~/.brain/.env` when unset in their own environment -- that file is the single place to flip it), `BRAIN_LOG_DIR` (default `~/.brain/logs`), `JEV_MODEL=jev-1.13.0`.
- Logs: `~/.brain/logs/server.log`, `~/.brain/logs/hook.log`, `~/.brain/logs/guard.log` (JSONL, see below) -- all under `BRAIN_LOG_DIR` when set.
- Timestamps: every `created_at`, `valid_to` and `approved_on` is ISO-8601 UTC with a literal `Z` suffix and millisecond precision (`strftime('%Y-%m-%dT%H:%M:%fZ','now')` in SQL, `new Date().toISOString()` on the TS side). The outcome gate and `/api/needs` compare `created_at` lexically against an ISO cutoff (`created_at < ?`), which relies on every writer using the same `YYYY-MM-DDTHH:MM:SS.sssZ` shape.
- Dependencies: `@modelcontextprotocol/server@2.0.0`, `@modelcontextprotocol/node@2.0.0`, `zod@4.6.5` -- 3 direct dependencies (6 packages installed: plus `@modelcontextprotocol/core`, `hono`, `@hono/node-server`). Nothing else at runtime.

## Identity

`Who = { agent: string; scope: 'full' | 'admin'; read?: boolean; write?: boolean; projects?: string[] | null }` (`src/verbs.ts`). The MCP path (`/mcp`) builds it with `whoIs(req)`: `agent` = `?agent=` query param on the request URL (`/mcp?agent=codex`), default `unknown`; `scope` is always `'full'`. `whoIs()` also looks `agent` up in `agent_policy` (see below); a matching row sets `read`/`write`/`projects` from it, no row leaves all three `undefined`. `POST /api/call` (the UI) builds it itself in `apiCall`: `agent` = `body.agent` (default `'ui'`), `scope` is always `'admin'`, `read`/`write`/`projects` never set -- the UI is a trusted local caller, so this is the only path with edit/delete powers `'full'` never has (see `update()` and the four `ui_only` verbs below). `callVerb()` is the single enforcement point for both scope and agent policy: on entry, `scope: 'admin'` is normalized to `{agent, scope: 'admin'}` (dropping any `read`/`write`/`projects`), so admin bypasses agent policy unconditionally; for `scope: 'full'`, a verb whose `access` is `'read'` is refused when `who.read === false`, `'write'` when `who.write === false`, and read/write handlers apply `scopeClause()`/`scopeParam(who.projects)` (reads) or `assertWriteProject()` (writes) against `who.projects`. `mcpServerFor(read, write)` (`src/server.ts`, one `McpServer` cached per read/write pair) mirrors this by only registering tools that pair allows -- cosmetic, `callVerb()` is still the real check. v2 will read a bearer token into `whoIs`; handlers still never look at the request themselves.

## Verbs (the one table in `src/verbs.ts`)

Each entry: `{ name, description, input: zodObject, handler(args, who) -> result, access: 'read'|'write', ui_only?: true }`. `access` gates two things: `callVerb()`'s agent-policy check (a `'read'` verb needs `who.read !== false`, a `'write'` verb needs `who.write !== false`; see Identity) and, for a non-`ui_only` verb, which `mcpServerFor(read, write)` combinations register it as a tool. MCP tools and `POST /api/call` are both generated from this table, but a `ui_only` verb (`delete_node`, `delete_edge`, `agent_policies`, `set_agent_policy`) is skipped by the MCP registration loop in `src/server.ts` -- it exists only as a `POST /api/call` verb, which always runs with `scope: 'admin'` (see Identity). Tool names are the verb names (clients register the server as `brain`, so Claude Code sees `mcp__brain__search`).

| verb | access | input | result |
|---|---|---|---|
| `ask` | read | `{question: string, project?: string, limit?: number=10}` | `{intent: 'rules'\|'lessons'\|'dead_ends'\|'history'\|'general', hits: Hit[] (with `score` 0..1), expanded: {nodes: Node[], edges: Edge[]}, jev: boolean, footer: string[]}` |
| `search` | read | `{query?: string, kind?, status?, verdict?, project?, limit?: number=20}` | `{hits: Hit[], footer}` |
| `context` | read | `{id: number, hops?: number=2}` (cap 25 nodes) | `{nodes: Node[], edges: Edge[], footer}` |
| `get` | read | `{ids: number[]}` | `{nodes: (Node & {edges_out: Edge[], edges_in: Edge[]})[], footer}` |
| `log` | write | `{kind, title, why?, status?, verdict?, confidence?, project?, alternatives?: string[], evidence?: string[], files?: string[], guard?: Guard, links?: {type, to: number}[]}` | `{id, created: boolean, links: number, footer}` (`created:false` = hash hit) |
| `link` | write | `{src: number, type: string, dst: number}` | `{ok: true, footer}`. Both `src` and `dst` must be visible (`assertVisible()`). For `scope: 'full'` only: `src` must also be writable (`assertWriteProject()`, same rule `log()`/`update()`/`approve_rule()` apply -- creating an edge writes through its source); for a mutating edge type (`supports`/`refutes`/`supersedes` -- each drives a DB trigger that flips `dst`'s status or retires it on insert, same effect as a direct write) `dst` must be writable too, not just visible. Every other edge type leaves `dst` visibility-only. `scope: 'admin'` is exempt from both checks. |
| `update` | write | `{id, rev, title?, why?, status?, verdict?, confidence?, alternatives?, evidence?, files?, guard?: Guard, project?}` | `{id, rev, footer}`; stale rev -> error `conflict: #id is at rev N`. **scope `full`**: refuses every field change on an approved rule (propose a new rule that supersedes it instead, sending `guard` counts as a field change too); refuses any rule status change outside that (only `approve_rule`/`supersedes` move it); refuses a retired/superseded node entirely (`valid_to` set); refuses `verdict`/`guard` outright. **scope `admin`** (`POST /api/call` only): none of the above refusals apply -- may edit every field of an approved rule, and may edit a retired/superseded node (its `WHERE` drops the `valid_to IS NULL` clause `full` keeps). Admin-only fields: `verdict` (conclusion only, `good\|bad\|mixed`, validated the same as `log()`); `guard` (rule only, regexes validated by the same `validateGuardRegexes()` `log()` uses, merged into `props.guard`); rule `status`: `'retired'` also sets `valid_to` to now; `'proposed'` clears `valid_to`/`approved_by`/`approved_on`; `'approved'` is refused (`use approve_rule`) even for admin. Thought `status` (`open\|validated\|refuted`) is unchanged for either scope. Also refused before any of the above, for `scope: 'full'` only: a write outside `who.projects` (`assertWriteProject()`, same rule `log()`/`link()`/`approve_rule()` apply -- see the `agent_policy` section below). |
| `approve_rule` | write | `{id: number, approved_by: string}` | `{id, status: 'approved', footer}` |
| `delete_node` (`ui_only`) | write | `{id: number}` | `{id, title, deleted: true, edges: number, footer: []}`. Deletes the node, every edge touching it (`src = id OR dst = id`), and its `node_file` rows, in one transaction (the FTS row goes via the existing `node_fts_ad` trigger); frees the node's content hash. Past side effects are not undone -- e.g. a rule this node had retired via `supersedes` stays retired; deleting a conclusion removes its `supports`/`refutes` edges but the thought keeps the status they set. `#id not found` if it doesn't exist. |
| `delete_edge` (`ui_only`) | write | `{src: number, type: string, dst: number}` | `{ok: true, deleted: number, footer: []}` (`deleted` = SQLite's `changes`, 0 if no such edge). Deleting a `supports`/`refutes` edge does not flip the thought's status back. |
| `agent_policies` (`ui_only`) | write | `{}` (no fields, `.strict()`) | `{agents: {agent, read: boolean, write: boolean, projects: string[]\|null, last_write: string\|null}[], projects: string[]}`. `agents` is every agent with either a policy row or at least one written node, sorted by name -- an agent with a row but no writes yet still gets `last_write: null`; an agent with writes but no row shows the unrestricted default (`read: true, write: true, projects: null`). `projects` is every distinct non-null `node.project`, for populating a project picker. No `footer` key (unlike every other verb above). |
| `set_agent_policy` (`ui_only`) | write | `{agent: string (min 1), read: boolean, write: boolean, projects: string[]\|null}` | `{ok: true}`. Upserts one `agent_policy` row (`ON CONFLICT(agent) DO UPDATE`); `projects: null` clears the column back to "every project". No `footer` key. |

Types: `Hit = {id, kind, title, status, verdict, project, created_at}`; `Node = {id, kind, title, why, project, status, verdict, confidence, props (parsed object), approved_by, approved_on, agent, rev, created_at, valid_to}`; `Edge = {src, dst, type, created_at}`; `Guard = {tool: string (regex on tool_name), deny_if?: string (regex over JSON.stringify(tool_input)), judge?: string (yes/no question for Jev)}`.

## `agent_policy` (per-agent access, `src/schema.sql`)

| column | type | default | meaning |
|---|---|---|---|
| `agent` | TEXT | -- | primary key, matches the `?agent=` a caller sends |
| `can_read` | INTEGER (0\|1) | 1 | gates every `access: 'read'` verb for that agent under `scope: 'full'` |
| `can_write` | INTEGER (0\|1) | 1 | gates every `access: 'write'` verb for that agent under `scope: 'full'` |
| `projects` | TEXT, `json_valid` or NULL | NULL | NULL = every project; a JSON array of project names = reads/writes scoped to those (plus company-wide `project IS NULL` nodes, always readable, never writable by a scoped agent) |
| `updated_at` | TEXT | now | set on every `set_agent_policy` upsert |

No row for an agent at all (not merely `projects IS NULL`) means fully unrestricted: `can_read`/`can_write` true, every project -- identical to every install before this table existed. `whoIs()` (Identity, above) is the only reader; `set_agent_policy` (`ui_only`) is the only writer other than a raw SQL statement.

Errors from handlers are thrown `Error(message)`; MCP returns them as `isError: true` text; `/api/call` returns HTTP 400 `{error: message}`.

`guard_frozen` (the DB trigger that used to block any change to an approved rule's guard, for every caller) is gone (`DROP TRIGGER IF EXISTS guard_frozen` in `schema.sql`, applied to the live DB on next start too). The invariant now lives in `update()`: refused for scope `full`, allowed for scope `admin`. `rule_approve_guard` is narrowed the same way, from `WHEN NEW.kind='rule' AND NEW.status='approved'` to also require `OLD.status IS NOT 'approved'` -- unnarrowed, it fired on *any* update to an already-approved rule (an UPDATE that doesn't touch `status` still carries the old value into `NEW.status`), which would have blocked admin's plain field edits too. It still blocks a raw-SQL resurrection of a retired rule.

`footer` is an array of short strings the server appends to every result: outcome gate (`"#18 has waited 16 days for an outcome. If you know it, log a conclusion that evaluates it."`, max 3 lines, actions older than 14 days with no `evaluates` edge, current, same project when known), unlinked warning after a `log` with zero links, Jev link suggestions after `log`.

## HTTP (all JSON, loopback only, host/origin validated)

- `POST /mcp` Streamable HTTP MCP, stateless (new transport per request); every hit updates the in-memory `seenAgents` map (`whoIs(req).agent -> Date.now()`), surfaced on `GET /api/version` below.
- `GET /` -> `public/index.html`. `GET /api/version` -> `{version: number, nodes: number, agents: [{agent, last_write}], jev: 'on'\|'off', guards: 'shadow'\|'on'\|'off', repo_dir: string, seen: [{agent, last_seen}]}`. `version` is an in-memory counter bumped after every committed write. `repo_dir` is the repo root (parent of `src/`, derived from `import.meta.url`, same technique as `PUBLIC_DIR`). `seen` lists every agent that has hit `/mcp` since the server started, `last_seen` ISO-8601 UTC with a `Z` suffix; empty until the first `/mcp` request.
- `GET /api/graph?range=24h|7d|30d|all&project=<name>|_all&limit=2000` -> `{nodes: Node[], edges: Edge[], version}`; nodes = most recent in range, edges = those with both ends in the set. `GET /api/graph?ids=1,2,3&hops=2` -> same shape, the union of `context()` for those ids.
- `GET /api/needs?project=` -> `{proposed_rules: Node[], stale_actions: (Node & {days: number})[], guard_events: GuardEvent[] (last 20)}`.
- `POST /api/call` `{verb, args, agent?}` -> the verb result, run with `scope: 'admin'` (the only admin-scope entry point -- see Identity). `agent` defaults to `ui`. This is the only way to reach any `ui_only` verb (`delete_node`, `delete_edge`, `agent_policies`, `set_agent_policy`) -- none of the four are ever registered as MCP tools. A successful `delete_node` also appends one line to `server.log`: `ui deleted #<id> "<title>"`.
- `GET /api/install` -> `installStatus()` from `src/install.ts`: `{url, repo_dir, clients: [{id, name, installed: true|false|'partial', files: [{path, ok}], snippet, gets, restart}]}` for the 5 real clients (`claude-code`, `codex`, `cursor`, `gemini`, `claude-desktop`) plus a trailing pseudo-client `{id: 'other', installed: null, files: [], snippet: 'Streamable HTTP MCP at <base>/mcp?agent=<your-agent-name>', ...}` with no install action. Read-only, never writes. `installed` is `true` when every one of a client's files already carries the brain wiring, `false` when none do, `'partial'` otherwise. `snippet` is the copy-paste text for doing the same wiring by hand (for `claude-code`: the `claude mcp add` line, the hooks JSON block, and the two `ln -s` lines, worded as in README.md; for the rest: each file's path plus the block to paste into it).
- `POST /api/install` `{client}` -> `install(client)`: `{client, changed: string[], skipped: string[], backups: string[], errors: [{path, error}]}`. `client` must be one of the 5 real ids (400 `{error}` otherwise). Every file write backs up an existing file first (`<file>.bak-brain-<YYYYMMDD-HHMMSS>`, copied before writing), is skipped (no write, no backup) when that file already satisfies its own `installed when` check, and unparsable JSON is left byte-identical with `{path, error}` recorded instead of a write. Claude Code's hooks merge only *appends* missing groups to `hooks.<Event>`, one per mode (`SessionStart`/`start`, `UserPromptSubmit`/`recall`, `PreToolUse`/`pre`, `PostToolUse`/`mark`, `Stop`/`stop`), never touching an existing group. One `server.log` line per changed file (`{event:'install', client, path}`).
- `POST /api/recall` `{prompt, project?}` -> `{hits: Hit[]}` max 3. `buildFtsQuery` drops a ~60-word English stopword list plus tokens under 3 chars before wildcarding (empty query -> `{hits: []}` with no DB hit). FTS top 10 -> Jev noul >= 0.6, top 3; Jev off -> keep only candidates with `bm25 <= -4` (SQLite bm25 is negative, more negative = better), then top 3; empty array when nothing clears the bar.
- `POST /api/pre` `{tool_name, tool_input, project?, repo_root?, session_id}` -> `{decision: 'allow'\|'deny'\|'ask', reason?: string, context?: string}`. `repo_root` is the absolute git toplevel of `cwd` (empty/absent when not a repo); the hook sends it on every call. Order: **regex guards** first -- live rules (`kind='rule' AND status='approved' AND valid_to IS NULL AND (project IS NULL OR project = :project)`) whose `props.guard.deny_if` is set; `new RegExp(guard.tool,'i').test(tool_name)` and `new RegExp(guard.deny_if).test(JSON.stringify(tool_input))` both matching -> an immediate `{decision:'deny', reason:'Blocked by brain rule #<id>: <title>. ...'}` and a `mode:'regex'` GuardEvent, before semantic guards or advice ever run. Then **semantic guards** (Jev, only when some live rule's `guard.tool` matches `tool_name` and it has `guard.judge`) with bands: noul >= 0.85 deny, 0.5..0.85 ask, else allow; in `shadow` mode never denies, logs what it would do. Then **advice**: for `tool_name` in `Edit|Write|MultiEdit|NotebookEdit`, up to 2 nodes from `node_file` matching `tool_input.file_path` made repo-relative -- strip `repo_root + '/'` when the path starts with it, else (absolute path, `project` known) keep only what follows the last `/<project>/`, else use the path as given -- then an **exact** match (`nf.path = rel`, no suffix `LIKE`) scoped to `nf.project = project OR nf.project IS NULL`; each id shown once per `session_id` (in-memory set), formatted `"Brain: decisions that touched this file: #12 <title>, #40 <title>. context(12) for more."`. `BRAIN_GUARDS=off` (env, loaded from `~/.brain/.env`) skips both regex and semantic guards; advice still runs.
- HTTP hygiene: a malformed JSON body on any `POST` -> `400 {error}`; a body over 1 MB -> `413 {error}` before it is parsed.

`GuardEvent` (one JSON per line in `~/.brain/logs/guard.log`): `{ts, session_id, tool, rule_id, title, mode: 'regex'\|'semantic', decision: 'deny'\|'ask'\|'would_deny'\|'would_ask'\|'allow', p?: number}`. The hook appends regex events; the server appends semantic ones.

## Hooks -> server

`hooks/brain-hook.sh <mode>` reads the Claude Code hook JSON on stdin. Modes: `start` (SessionStart), `recall` (UserPromptSubmit), `pre` (PreToolUse), `mark` (PostToolUse), `stop` (Stop), `--selftest`. Everything fails open (exit 0, nothing on stdout) on any error, logging to `~/.brain/logs/hook.log`. `start` reads the DB with `sqlite3 -readonly` so it works with the server down. `recall` and `pre` call the server first (`curl -s -m 1.5` / `-m 2.5`); `pre` only falls back to its own `sqlite3 -readonly` + `jq` regex-guard path (no semantic guards, no advice) when that call is unreachable -- curl exits non-zero or the response body is empty -- never merely because it doesn't like the server's answer. Project = basename of `git rev-parse --show-toplevel` from `cwd`, else null. Marker file: `${TMPDIR:-/tmp}/brain-nudge-<session_id>`.

## Bootstrap (`install.sh`, `src/setup.ts`)

`install.sh` (repo root): `curl -fsSL <raw-url>/install.sh | bash`. Flags: `--yes` (no prompts anywhere, incl. Homebrew offers; passes `--yes` to `setup.ts`), `--no-service` (skip installing the macOS launchd service; on non-Darwin the service step is always skipped, with a printed `npm start` hint instead). Env: `MUSE_BRAIN_DIR` (default `$HOME/.muse-brain`, the clone/update target), `MUSE_BRAIN_REPO` (default `https://github.com/yahavf6/muse-brain.git`); a script already running from inside a real checkout (a `src/server.ts` next to it) uses that checkout instead of cloning, unless the caller set `MUSE_BRAIN_REPO` explicitly. Also reads `BRAIN_PORT` (default 4747) for its post-install readiness poll. Order: preflight (`git`/`curl`/`sqlite3` fixit-only; `jq`/`node>=24` offer `brew install` first) -> clone or `git pull --ff-only` -> `npm ci --omit=dev` -> `scripts/service.sh install` (Darwin, unless `--no-service`) -> `node src/setup.ts --yes` (with `--yes` or no `/dev/tty`) or `node src/setup.ts < /dev/tty` otherwise (its own stdin is the piped script, not a terminal, so prompts read from the tty directly).

`src/setup.ts`: `node src/setup.ts` (or `npm run setup`). Flag: `--yes` -- never prompts (every question takes its default) and skips the ASCII intro. `main()` also treats a non-TTY stdin as `--yes` even without the flag (`opts.yes = yesFlag || !process.stdin.isTTY`), so e.g. `install.sh`'s own `node src/setup.ts --yes` and its `node src/setup.ts < /dev/tty` fallback (stdin explicitly reattached to the terminal, so it stays interactive) are the only two paths it takes. Marker file `~/.brain/.intro-shown`: an empty file written after the ASCII intro finishes playing once; its presence makes every later run print just the one-line wordmark instead of replaying the animation. Intro is also skipped outright (regardless of the marker) when `opts.yes`, `!process.stdout.isTTY`, `process.env.CI`, `process.env.NO_COLOR`, `process.env.TERM === 'dumb'`, or a terminal narrower than 40 columns. Flow: reachability check (`GET /api/version`, 1.5s timeout) -> client status via `installStatus()` (`src/install.ts`, whose `Client` shape gained `agent`/`detect()` for this) -> if every detected client is already fully wired, ask to change access, else offer to connect all with read+write on every project (`[Y/n]`) or walk each one's access (`promptAccess`/project list, upserted via `set_agent_policy` when it differs from the agent's *current* state -- no row and the unrestricted default both write nothing, but choosing the default when a restrictive row already exists still writes, so re-granting full access actually clears it).

## Seed

`scripts/seed-demo.ts` refuses to run against a DB that already has any node, unless `--force` is passed (prints the existing count and exits 1); it always prints the DB path it wrote to. Every node it seeds -- rules included -- is forced to `project: 'demo'` in the one `log()` wrapper the script uses, so a scoped query (`project IS NULL OR project = <repo>`) can never inject a demo rule or guard into a real repo.

## Jev

`src/judge.ts`: `judge(state: unknown, questions: Record<string, Question>, timeoutMs: number): Promise<Answers | null>`. `POST https://api.typesafe.ai/v1/systemone`, header `Authorization: Bearer $TYPESAFE_API_KEY`, body `{state, model, questions}`. Question: `{type: 'noul', instructions, criteria?: {true, false}}` | `{type: 'choice', instructions, criteria: {option: description|null}}` | `{type: 'score', instructions, criteria: string[]}`. The HTTP body is `{model, answers: {[id]: Answer}, usage}`; `judge()` returns only the `answers` map: `{[id]: {type:'noul', noul: number} | {type:'choice', choice, probabilities, confidence} | {type:'score', score, probabilities, confidence}}`. Returns `null` on missing key, `BRAIN_JEV=off`, timeout (`AbortSignal.timeout`), non-2xx, invalid JSON, or a body without `answers`. Never throws. Never called before a write commits.
