# Bench results, 2026-09-22

Measures synthetic decision graphs written through the real `log` verb (zod validation, `BEGIN IMMEDIATE`, content hash, FTS triggers, edge triggers, and the reply footer), plus `ask`/`search`/`context`/`get` latency and hook overhead, at increasing graph size. This run includes the `action_open` index fix from commit e2d1237. Reproduce with `npm run bench` (default sizes 1,000 / 10,000 / 100,000); add `BENCH_SIZES=1000,10000,100000,1000000 npm run bench` to include 1M, expect it to take hours.

## Reading the numbers

- Every write pays for the reply footer: `log()` (`src/verbs.ts:513-515`) calls `footer(who, args.project)` for the outcome-gate lookup and `jevLinkSuggestions(id, args.kind, args.title, why)` for the "possibly related" suggestions, on every single call. The outcome-gate lookup now uses the `action_open` index and stays flat; the suggestions call is one FTS `bm25 ORDER BY` query per write, and its cost is what grows with size.
- The synthetic corpus draws titles and whys from a small, fixed word list, so any given term sits on a much larger share of rows than it would in a real brain. That makes the FTS `MATCH` behind `jevLinkSuggestions` touch far more candidates as the graph grows, which is why `log` p50 climbs with size here more than it would against organic, varied text.
- `context` (a 2-hop recursive CTE over the edge table) and `get` (by id) stay flat across all three sizes because both are index walks from a known starting point, not scans.
- 1,000,000 was not run to completion in this session, for time reasons; the script supports it via `BENCH_SIZES`.
